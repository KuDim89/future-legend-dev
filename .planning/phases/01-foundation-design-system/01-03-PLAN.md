    Replace `lib/SmoothScrollProvider.tsx` stub with the full Lenis + GSAP ScrollTrigger integration. This file must be marked `'use client'` — it uses browser APIs (`gsap.ticker`, `useRef`, `useEffect`).

    File structure:
    - `'use client'` at top
    - Imports: `ReactLenis` from `'lenis/react'`, `gsap` from `'gsap'`, `ScrollTrigger` from `'gsap/ScrollTrigger'`, `useEffect` and `useRef` from `'react'`
    - `gsap.registerPlugin(ScrollTrigger)` at MODULE SCOPE (not inside useEffect or useGSAP — this is the one place ScrollTrigger is registered globally)
    - Component `SmoothScrollProvider` receiving `{ children: React.ReactNode }`
    - `lenisRef = useRef<any>()` — used by ReactLenis ref prop
    - `useEffect` with this exact logic:
      - Define `function update(time: number) { lenisRef.current?.lenis?.raf(time * 1000) }`
      - `gsap.ticker.add(update)` — Lenis RAF runs inside GSAP tick
      - `gsap.ticker.lagSmoothing(0)` — prevents scroll drift from lag compensation
      - Return cleanup: `() => gsap.ticker.remove(update)`
    - Return JSX: `<ReactLenis root ref={lenisRef} options={{ lerp: 0.1, duration: 1.2, syncTouch: true, autoRaf: false }}>{children}</ReactLenis>`

    The `autoRaf: false` option on ReactLenis is CRITICAL — it disables Lenis's own requestAnimationFrame loop. Without it, Lenis runs its own RAF in parallel with GSAP's ticker, causing scroll desync (Pitfall 5).

    Do NOT use `ScrollTrigger.scrollerProxy()` — this is the old Lenis v0 pattern and is not in the current Lenis v1 docs.

    Do NOT add `lenis.on('scroll', ScrollTrigger.update)` as a primary approach — ticker sync alone is sufficient. If testing reveals ScrollTrigger fires at wrong positions, add it as a fallback.

    Confirm `app/[lang]/layout.tsx` wraps children with `SmoothScrollProvider` inside `<Providers>`. The provider order in `<body>` should be: `<Providers><SmoothScrollProvider>{children}</SmoothScrollProvider></Providers>`. This means theme context is available inside the scroll provider.
