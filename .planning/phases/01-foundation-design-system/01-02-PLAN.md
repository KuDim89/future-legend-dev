<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Google Fonts CDN → next/font | Fonts are downloaded at build time, not served from Google CDN at runtime — no external requests from user browsers |
| localStorage → next-themes | Theme preference stored in `fl-theme` key — only a string ('dark'/'light'), no PII |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | localStorage (fl-theme key) | accept | Stores only 'dark' or 'light' string. No PII. No session data. No auth tokens. |
| T-02-02 | Tampering | SCSS token system | accept | Tokens are build-time generated CSS — cannot be modified at runtime by users. No injection surface. |
| T-02-03 | Tampering | next-themes anti-FOUC script | accept | next-themes injects a well-audited inline `<script>` that reads localStorage and sets `data-theme`. The script is hardcoded by the library — no user input flows into it. XSS risk is negligible. |
| T-02-04 | Information Disclosure | Google Fonts (build-time download) | mitigate | `next/font/google` downloads fonts at `next build` time and self-hosts them. User browsers never make requests to `fonts.googleapis.com` or `fonts.gstatic.com`. No user IP is sent to Google. |
| T-02-SC | Tampering | npm install (supply chain) | accept | All packages in Package Legitimacy Audit have [VERIFIED] disposition — sass, next-themes, framer-motion, gsap, lenis all verified against official npm registry and source repos. |
</threat_model>
