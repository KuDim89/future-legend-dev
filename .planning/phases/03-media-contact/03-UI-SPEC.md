## Spacing Scale

Spacing tokens are defined in `styles/_tokens.scss` on an 8px base unit. Phase 3 uses the following subset:

| Token | CSS Variable | Value | Phase 3 Usage |
|-------|-------------|-------|---------------|
| xs | `--space-1` | 4px | Icon gaps, input icon padding |
| sm | `--space-2` | 8px | Label-to-input gaps, inline metadata |
| md | `--space-4` | 16px | Card internal padding (mobile), form field spacing |
| lg | `--space-6` | 24px | Card internal padding (desktop), grid gap |
| xl | `--space-8` | 32px | Layout column gap (tablet) |
| 2xl | `--space-12` | 48px | Title margin-bottom (matches TrophiesSection pattern) |
| 3xl | `--space-16` | 64px | Section vertical padding (mobile) |
| 5xl | `--space-24` | 96px | Section vertical padding, desktop |

Section padding pattern (matches all Phase 2 sections exactly):
- Mobile: `padding: var(--space-16) var(--space-4)` → 64px top/bottom, 16px sides
- Desktop (`lg` breakpoint): `padding: var(--space-24) var(--space-8)` → 96px top/bottom, 32px sides

Grid gap (matches TrophiesSection exactly): `gap: var(--space-6)` → 24px

Exceptions: Masonry column gap via `react-masonry-css` classname `.my-masonry-grid_column` uses `padding-left: var(--space-6)` (24px). Touch target minimum on play button overlay: 44px diameter.

## Section Layout Contracts

### 1. HighlightsSection (`#highlights`)

**Focal point:** Crimson (`var(--color-accent)`) play button overlay centered over the hovered video card thumbnail — the first thing the eye lands on in any card hover state.

**Structure:**
```
<section id="highlights">
  <h2 className="reveal-item">Highlights</h2>
  <p className="reveal-item">{intro text}</p>
  <ul role="list" className={grid}>
    {videos.map(video => (
      <li role="listitem" className="reveal-item">
        <VideoCard video={video} />  <!-- 'use client' component managing clicked state -->
      </li>
    ))}
  </ul>
</section>
```

**Grid CSS (mirrors TrophiesSection.module.scss exactly):**
```scss
.grid {
  display: grid;
  grid-template-columns: 1fr;
  gap: var(--space-6);
  list-style: none;
  padding: 0;
  margin: 0;

  @include respond-to('sm') {           // 576px
    grid-template-columns: 1fr 1fr;
  }

  @include respond-to('lg') {           // 1024px
    grid-template-columns: repeat(3, 1fr);
  }
}
```

**VideoCard states:**

| State | Visual Contract |
|-------|----------------|
| Default | `var(--color-bg-elevated)` card bg, border `1px solid var(--color-border)`, border-radius 4px. YouTube thumbnail image fills card top (aspect-ratio: 16/9, `object-fit: cover`). Card title below thumbnail: `var(--text-base)` / weight 700 / `var(--font-heading)` / uppercase / `var(--color-text)`. Padding: `var(--space-4)` |
| Hover | Framer Motion `whileHover`: scale 1.02, duration 0.2s ease-out. Play button overlay appears: crimson circle (`var(--color-accent)`) 48px diameter centered over thumbnail, triangle icon (Lucide `Play`, 20px, white fill). Overlay bg: `var(--color-overlay)` covers the thumbnail area only |
| Focus (keyboard) | `outline: 2px solid var(--color-accent)`, `outline-offset: 2px` — matches site-wide focus pattern |
| Playing | Clicked state: `<img>` replaced by `<YouTube>` component (`autoplay: 1`). YouTube iframe fills the card top slot at 16:9 aspect ratio. Card title remains below. No overlay. No scale animation on the iframe container |
| Loading (iframe init) | No visible loading state — YouTube handles its own loader inside the iframe |

**Play button overlay:**
- Position: `position: absolute`, centered horizontally and vertically within the thumbnail container
- Circle: 48px × 48px, `background: var(--color-accent)`, `border-radius: 50%`
- Icon: Lucide `Play`, 20px, `color: #ffffff`, offset 2px right (visual centering correction for triangle)
- Hover on circle: `background: var(--color-accent-hover)` — CSS transition 0.15s, NOT Framer Motion (icon container hover, not mount/unmount)
- Touch target: 48px diameter meets minimum — no adjustment needed

**Lite-embed pattern contract:**
- Initial DOM: `<img src="https://img.youtube.com/vi/{videoId}/maxresdefault.jpg" alt="{title} — highlight video" loading="lazy" />` inside the thumbnail slot
- On click: React state `isPlaying = true` → `<img>` unmounts (Framer Motion `exit: { opacity: 0 }`, duration 0.15s) → `<YouTube>` component mounts with `opts={{ playerVars: { autoplay: 1 } }}`
- No `<iframe>` in DOM until click (satisfies MEDIA-03)

**GSAP animation:** `useScrollReveal(containerRef)` — section title, intro paragraph, and each `<li>` carry `.reveal-item` class. Entrance: opacity 0→1, y 40→0, stagger 0.1s, power1.out, trigger: `top 80%`.

**Framer Motion animation:** VideoCard hover (scale + overlay appearance). Thumbnail `<img>` exit on click (opacity 0→ unmount). YouTube component mount (opacity 0→1, duration 0.2s).

Animation ownership: GSAP owns scroll entrance. Framer Motion owns hover + click state swap. No element animated by both.

### 2. GallerySection (`#gallery`)

**Focal point:** Hovered photo card with `var(--color-overlay)` brightness overlay at opacity 0.5 — the hover state draws the eye to the currently-targeted photo and signals click-to-expand affordance.

**Structure:**
```
<section id="gallery">
  <h2 className="reveal-item">Gallery</h2>
  <p className="reveal-item">{intro text}</p>
  <Masonry
    breakpointCols={{ default: 3, 768: 2, 480: 1 }}
    className="masonry-grid"
    columnClassName="masonry-grid_column"
  >
    {photos.map((photo, index) => (
      <div className={`${styles.photoWrapper} reveal-item`} onClick={() => openLightbox(index)}>
        <img src={photo.src} alt={photo.alt} loading="lazy" />
        <div className={styles.photoOverlay} aria-hidden="true" />
      </div>
    ))}
  </Masonry>
  <Lightbox open={lightboxOpen} close={closeLightbox} slides={slides} plugins={[Fullscreen, Zoom]} />
</section>
```

**Masonry CSS (global scope — react-masonry-css requires global class names):**
```scss
// In GallerySection.module.scss — but masonry classes must leak to global
:global(.masonry-grid) {
  display: flex;
  margin-left: calc(-1 * var(--space-6));   // negative margin compensates column padding
  width: auto;
}

:global(.masonry-grid_column) {
  padding-left: var(--space-6);
  background-clip: padding-box;
}
```

**Photo card states:**

| State | Visual Contract |
|-------|----------------|
| Default | Raw `<img>` with `border-radius: 4px`, `width: 100%`, `display: block`, `margin-bottom: var(--space-6)` (column gap). No border. No card chrome |
| Hover | Framer Motion `whileHover` on wrapper: scale 1.02, duration 0.2s ease-out. Overlay div fades in: `background: var(--color-overlay)`, `border-radius: 4px`, `opacity: 0→0.5`. Cursor: pointer |
| Focus (keyboard) | `outline: 2px solid var(--color-accent)`, `outline-offset: 2px` on wrapper |
| Open in lightbox | Framer Motion exit on wrapper: none (lightbox opens on top, photo stays in grid) |

**Lightbox configuration (yet-another-react-lightbox):**

| Setting | Value | Rationale |
|---------|-------|-----------|
| `plugins` | `[Fullscreen, Zoom]` | Fullscreen for immersive view; Zoom for photo detail. No Download plugin (player controls photo distribution) |
| Toolbar items | Close button (default), Fullscreen toggle, Zoom in/out | Minimal — no download, no share, no captions (captions deferred per CONTEXT.md) |
| Keyboard navigation | Enabled (yarl default) | Arrow keys prev/next, Escape to close |
| Background | `rgba(0,0,0,0.92)` | yarl default — sufficiently dark for all themes |
| Animation | yarl default slide | Consistent with library defaults; no custom override |

**GSAP animation:** `useScrollReveal(containerRef)` on section container — section title, intro paragraph, each photo wrapper carry `.reveal-item` class. Entrance: opacity 0→1, y 40→0, stagger 0.1s, power1.out, trigger: `top 80%`.

**Framer Motion animation:** Photo card hover (scale + overlay opacity). Lightbox open/close — yarl handles internally; no Framer Motion wrapper around the Lightbox component.

Animation ownership: GSAP owns scroll entrance. Framer Motion owns hover. yarl owns lightbox transitions. No element animated by both GSAP and Framer Motion.

### 3. ContactSection (`#contact`)

**Focal point:** Accent-filled "Send Message" submit button (`background: var(--color-accent)`) at the base of the form — the sole crimson element in a field of muted surfaces, directing the eye and signalling the primary action.

**Structure:**
```
<section id="contact">
  <h2 className="reveal-item">Contact</h2>
  <p className="reveal-item">{intro text}</p>

  <AnimatePresence mode="wait">
    {formState === 'success'
      ? <SuccessMessage key="success" />   // Framer Motion fade in
      : <ContactForm key="form" formState={formState} onSubmit={handleSubmit} />
    }
  </AnimatePresence>
</section>
```

**Form layout:**
- Max width: 640px, `margin: 0 auto` — centered single-column form
- Fields stack vertically: name → email → phone → message → honeypot (hidden) → submit
- Field spacing: `margin-bottom: var(--space-6)` between each field group
- Submit button: full width at mobile, `max-width: 240px` auto-right at `md` breakpoint (or full width throughout — consistent with MVP focus; use full width for simplicity)

**Input field visual contract:**
```scss
.field {
  display: flex;
  flex-direction: column;
  gap: var(--space-2);      // 8px between label and input
}

.label {
  font-family: var(--font-body);
  font-size: var(--text-sm);       // 14px
  font-weight: 400;
  color: var(--color-text-muted);
  text-transform: uppercase;
  letter-spacing: 0.08em;          // matches bioField pattern from AboutSection
}

.input,
.textarea {
  font-family: var(--font-body);
  font-size: var(--text-base);     // 16px
  font-weight: 400;
  color: var(--color-text);
  background: var(--color-bg-elevated);
  border: 1px solid var(--color-border);
  border-radius: 4px;
  padding: var(--space-4) var(--space-4);   // 16px all sides
  width: 100%;
  transition: border-color 0.15s ease;      // CSS only — Framer Motion does NOT own this

  &::placeholder {
    color: var(--color-text-muted);
  }

  &:focus {
    outline: 2px solid var(--color-accent);
    outline-offset: 2px;
    border-color: var(--color-accent);
  }
}

.textarea {
  min-height: 140px;
  resize: vertical;
}
```

**Honeypot field CSS (hidden from real users, visible to bots):**
```scss
.honeypot {
  position: absolute;
  left: -9999px;
  top: auto;
  width: 1px;
  height: 1px;
  overflow: hidden;
  // NOT display:none — bots skip display:none fields
}
```

**Submit button states:**

| State | Visual Contract |
|-------|----------------|
| Default | `background: var(--color-accent)`, color `#ffffff`, font `var(--font-heading)` uppercase, weight 700, size `var(--text-base)`, padding `var(--space-4) var(--space-8)` (16px 32px), border-radius 4px, full width. Icon: Lucide `Send`, 18px, left of label, `gap: var(--space-2)` |
| Hover | `background: var(--color-accent-hover)` — CSS transition 0.15s. NOT Framer Motion |
| Focus | `outline: 2px solid var(--color-accent)`, `outline-offset: 2px` |
| Loading (in-flight) | `disabled` attribute set. Icon changes to Lucide `Loader2` with CSS `animation: spin 1s linear infinite`. Label: "Sending…". `opacity: 0.7`. Cursor: not-allowed |
| Disabled (honeypot/time triggered) | Submission silently dropped — button re-enables, no visual feedback shown to user |

**Form states:**

| State | Visual Contract |
|-------|----------------|
| Default | Form visible, all fields empty, submit button default |
| Loading | Submit button in loading state (see above). All `<input>` and `<textarea>` elements get `disabled` attribute to prevent edits during flight |
| Success | Framer Motion `AnimatePresence` exits form (`opacity: 0`, `y: -10`, duration 0.3s, ease "easeOut"). Success message fades in (`opacity: 0→1`, `y: 10→0`, duration 0.4s, ease "easeOut"). Form DOM is unmounted — no field preservation |
| Error | Inline error appears below submit button with Framer Motion mount (`opacity: 0→1`, `y: 5→0`, duration 0.25s). Form stays fully visible and pre-filled. Error uses `role="alert"` for screen readers |

**GSAP animation:** `useScrollReveal(containerRef)` on section container — section title, intro paragraph, and form container carry `.reveal-item` class. Entrance: opacity 0→1, y 40→0, stagger 0.1s, power1.out, trigger: `top 80%`.

**Framer Motion animation:** Form ↔ success swap via `AnimatePresence`. Error message mount. Loading state spin is CSS animation (not Framer Motion) — spin is a continuous loop, not a lifecycle animation.

Animation ownership: GSAP owns scroll entrance. Framer Motion owns form/success swap and error message mount. CSS animation owns spinner. No element animated by both GSAP and Framer Motion.

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Video thumbnails keyboard-accessible | `<button>` wrapper (not `<div onClick>`) — receives focus, Enter/Space triggers play |
| Gallery photos keyboard-accessible | `<button>` wrapper — Enter/Space opens lightbox |
| Lightbox keyboard navigation | yarl default: Arrow keys prev/next, Escape close, Tab through toolbar |
| Form error announced | `role="alert"` on error container — announced immediately on mount |
| Success state announced | `role="status"` on success message — politely announced |
| Honeypot accessible name | `aria-hidden="true"` + `tabindex="-1"` on the input — hidden from AT |
| Spinner accessible label | `aria-label="Sending…"` on spinner icon, visually hidden text alongside |
| Loading state | `aria-busy="true"` on `<form>` during in-flight request |
| Image lazy loading | `loading="lazy"` on all `<img>` (thumbnails and gallery photos) — satisfies MEDIA-03 |
| Photo alt text | Required, non-empty, from `content/gallery.ts` `alt` field |
