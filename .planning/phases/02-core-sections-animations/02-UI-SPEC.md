### Hero Background Specification

**Dark navy + crimson gradient placeholder** (D-01):

```css
background: linear-gradient(
  135deg,
  var(--color-bg) 0%,
  #1A0A0E 50%,
  rgba(229, 0, 43, 0.15) 100%
);
```

This gradient reads as predominantly dark navy with a subtle crimson glow at the bottom-right — cinematic, not garish. The accent color appears at 15% opacity to suggest energy without overwhelming the player's name text. The `background-image` slot sits above this gradient as a separate layer (`background-image` property) so swapping in a real player photo requires no CSS restructuring.

```css
/* positioned absolutely over background-image layer */
```

## Section Heading Visual Treatment

This treatment applies to ALL non-hero section headings (About, Trophies, Club, Team, and stub section titles).

**Specification:**
- Font: Oswald, `--text-4xl` (49px desktop / `--text-3xl` 39px mobile), weight 700
- `text-transform: uppercase`
- Color: `--color-text`
- Below the heading text: a 40px × 3px crimson accent rule (`--color-accent`)
- Gap between heading text and accent rule: `--space-2` (8px)
- Accent rule is a `<span>` or `::after` pseudo-element — NOT an `<hr>` (semantic mismatch)
- Alignment: left-aligned (not centered) — scout-facing content reads left-to-right

**SCSS pattern:**
```scss
.sectionTitle {
  font-family: var(--font-heading);
  font-size: var(--text-4xl);
  font-weight: 700;
  text-transform: uppercase;
  color: var(--color-text);
  line-height: 1.1;
  margin-bottom: var(--space-12); // 48px gap between title and content

  &::after {
    content: '';
    display: block;
    width: 40px;
    height: 3px;
    background-color: var(--color-accent);
    margin-top: var(--space-2); // 8px below heading baseline
  }
}
```

Source: CONTEXT.md "Claude's Discretion" — section heading style. Researcher decision: uppercase Oswald with crimson accent rule.

## Hero Section — Full Visual Contract

### Layout

- `min-height: 100svh` (fallback `100vh`)
- `position: relative` — contains the parallax background and the text content layer
- `display: flex; align-items: center; justify-content: center` — vertically and horizontally centers text content
- No horizontal padding on the background layer. Text content layer: `padding: 0 var(--space-8)` (32px) on desktop, `0 var(--space-4)` (16px) on mobile
- `overflow: hidden` — prevents parallax bleed outside section bounds

### Parallax Architecture

Two child layers inside the hero section:

**Layer 1 — Background (GSAP-controlled):**
- `position: absolute; inset: 0; z-index: 0`
- Applied gradient (see Color section above)
- `will-change: transform` — GPU-promoted layer for smooth parallax
- GSAP animation: `yPercent: 30` over full scroll distance of hero height
- Speed ratio: **40% of scroll speed** — background moves 0.4px for every 1px scrolled
- Implementation: `gsap.to(bgRef.current, { yPercent: 30, ease: 'none', scrollTrigger: { trigger: heroRef.current, start: 'top top', end: 'bottom top', scrub: 1 } })`
- The background starts 15% larger than the hero (`height: 115%`) to avoid revealing the edge during parallax

**Layer 2 — Text content (Framer Motion-controlled, mount only):**
- `position: relative; z-index: 1`
- Contains: player name, position label, CTA button
- NO GSAP on this layer — Framer Motion owns mount entrance exclusively
- Text does NOT move on scroll. Only the background parallaxes.

### Hero Text Entrance (Framer Motion — D-04)

Staggered mount animation. Each element: `initial={{ opacity: 0, y: 20 }}` → `animate={{ opacity: 1, y: 0 }}`.

| Element | Delay | Duration | Easing |
|---------|-------|----------|--------|
| Player name | 0.2s | 0.7s | `easeOut` |
| Position label | 0.5s | 0.6s | `easeOut` |
| CTA button | 0.8s | 0.5s | `easeOut` |

Animation owner: Framer Motion. Trigger: component mount.

### Hero CTA Button

- Label: "Contact Me" (English placeholder — Phase 4 will i18n this)
- Action: smooth scroll to `#contact` anchor (Lenis handles smooth scroll behavior)
- `href="#contact"` — native anchor, no JS required for basic scroll
- Size: `padding: 14px 32px` (14px = `--space-3` + 2px; 32px = `--space-8`)
- Background: `--color-accent`
- Background hover: `--color-accent-hover`
- Text: `--color-text` (white in dark theme — sufficient contrast against crimson)
- Border-radius: 4px (consistent with card radius throughout Phase 2)
- Font: Roboto 700, `--text-base` (16px)
- Hover transition: `background-color 150ms ease`
- Hover animation owner: CSS transition only (not Framer Motion — too simple for a library animation)
- Focus: 2px solid `--color-accent`, 2px offset (`:focus-visible` only)
- Minimum touch target: 44px height (14px padding top + 16px line-height + 14px padding bottom = 44px — exactly at WCAG minimum)

Source: CONTEXT.md D-02, D-03. Researcher decision for button sizing and easing values.

### FIFA-Style Stat Bars (D-13, D-14)

6 attributes: Pace, Dribbling, Shooting, Passing, Physical, Defending.

**Single bar anatomy (top to bottom, per row):**
```
[Label]                              [Value]
[━━━━━━━━━━━━━━━━━━━━━━━░░░░░░░░░░]
 ▲ filled (--color-accent)             ▲ track (--color-border)
```

**Bar specifications:**
- Row layout: label left (`--color-text-muted`, Roboto `--text-sm` 14px, weight 400), value right (Oswald `--text-sm` 14px, weight 700, `--color-text`)
- Bar track: full width, 8px height, border-radius 4px, background `--color-border`
- Bar fill: `--color-accent` (#E5002B), width = `{value}%`, same height and border-radius as track
- Gap between label row and bar: `--space-1` (4px)
- Gap between each stat row: `--space-6` (24px)

**GSAP Scroll Animation (D-14):**
- Trigger: stat bar section enters viewport at `start: 'top 80%'`
- Each bar fill animates `width` from `0%` to `{value}%`
- Duration: 1.0s per bar
- Stagger: 0.15s between bars (slightly slower than section stagger — allows each bar to feel distinct)
- Easing: `power2.out` — fast initial fill, decelerates at the end (feels like a meter "loading")
- `scrub: false` — plays once, stays filled
- Animation owner: GSAP (scroll-triggered — per CLAUDE.md rule)
- Implementation: target `[data-stat-fill]` attribute selector within scoped container ref

**Important:** Bar fill width must be set via GSAP `from: { width: '0%' }` → `to: { width: '{value}%' }`. Do NOT use CSS transitions on the fill element — GSAP owns this animation.

Source: CONTEXT.md D-11 through D-14. Researcher decision: 8px bar height, 4px radius, 0.15s stagger, `power2.out` easing.

## Scroll Animation System — Full Contract

### `useScrollReveal()` Hook

All non-hero sections use this shared hook (D-10). The hook encapsulates the established ScrollFadeSection pattern.

**Hook signature:**
```typescript
function useScrollReveal(containerRef: RefObject<HTMLElement>): void
```

**Behavior:**
- Targets elements with the class `.reveal-item` inside the container scope
- Animation: `opacity: 0 → 1`, `y: 40 → 0`
- Duration: 0.8s
- Stagger: 0.1s
- Easing: `power1.out` (GSAP default — consistent with Phase 1 ScrollFadeSection)
- `scrub: false` — fires once on entry, elements stay visible
- ScrollTrigger: `start: 'top 80%'` (D-07)
- Owner: GSAP inside `useGSAP({ scope: containerRef })`

**Section title animates first (D-08):** The section title element carries `.reveal-item` and appears as the first item in DOM order. Stagger flows: title (0ms) → first content item (100ms) → second content item (200ms) → etc.

### Animation Ownership Summary (Phase 2)

| Element | Owner | Trigger | Pattern |
|---------|-------|---------|---------|
| Hero background parallax | GSAP | Scroll position | `gsap.to` with `scrub: 1` |
| Hero text entrance (name, position, CTA) | Framer Motion | Component mount | `initial/animate` with delay |
| All non-hero section entries | GSAP via `useScrollReveal()` | `top 80%` viewport | `gsap.from('.reveal-item', ...)` |
| Stat bar fill | GSAP | `top 80%` viewport | `gsap.from('[data-stat-fill]', ...)` |
| CTA button hover | CSS transition | `:hover` | `background-color 150ms ease` |
| Nav link hover | Framer Motion | User interaction | Inherited from Phase 1 |
| Mobile menu open/close | Framer Motion | State change | Inherited from Phase 1 |
| Stub sections | none | none | Static — no animation |

**Critical rule:** The hero background layer is animated by GSAP. The hero text content layer is animated by Framer Motion. These are separate DOM elements — the animation ownership rule is not violated.

Source: CLAUDE.md animation rule. CONTEXT.md D-03, D-04, D-06 through D-10, D-14.

## Accessibility Contract

Extends Phase 1 baseline. Phase 2 additions:

| Element | Requirement |
|---------|-------------|
| Hero section | `role="banner"` on the `<section>` element (landmark for screen readers) |
| Player name heading | `<h1>` — the primary page heading |
| Section headings | `<h2>` for all section titles (About, Trophies, Club, Team, Highlights, Gallery, Contact) |
| Bio grid | `<dl>` (definition list) with `<dt>` for labels and `<dd>` for values |
| Stat bars | `role="list"` on container, each stat as `role="listitem"`. Bar has `aria-label="{attribute}: {value} out of 100"` |
| Trophy cards | `role="list"` / `role="listitem"` |
| Logo placeholders | `alt="{clubName} crest"` — descriptive, not decorative |
| Foot icon | `aria-hidden="true"` (decorative — adjacent text already conveys the value) |
| CTA button | `<a>` element (not `<button>`) — it's navigation, not an action. `aria-label="Contact {player.fullName}"` |
| Reduced motion | `@media (prefers-reduced-motion: reduce)` — all GSAP animations must wrap their `gsap.from()` calls in a `!window.matchMedia('(prefers-reduced-motion: reduce)').matches` check. Framer Motion: use `useReducedMotion()` hook and skip animation variants. |

**Reduced motion contract:** When `prefers-reduced-motion: reduce` is active:
- Hero background: no parallax (static background)
- Hero text: appears immediately at full opacity (no fade-in)
- Section entries: appear immediately (no fade-in scroll animations)
- Stat bars: fill immediately to final value on section entry (no animated fill)

Source: WCAG 2.1 AA. WCAG 2.5.3 (label in name). WCAG 1.3.1 (info and relationships).

## Animation Ownership Reference (Full Phase 2 Summary)

Per CLAUDE.md: Framer Motion owns mount/unmount and hover. GSAP owns scroll-triggered sequences. Never animate the same element with both.

| Element | Owner | Trigger | Notes |
|---------|-------|---------|-------|
| Hero background layer | GSAP | Scroll (scrub: 1) | Separate DOM element from text layer |
| Hero text (name, position, CTA) | Framer Motion | Mount | `initial/animate`, no scroll involvement |
| About section entry | GSAP via `useScrollReveal()` | Scroll `top 80%` | `.reveal-item` scoped to section |
| Trophies section entry | GSAP via `useScrollReveal()` | Scroll `top 80%` | Section title + each card |
| Club section entry | GSAP via `useScrollReveal()` | Scroll `top 80%` | Section title + content block |
| Team section entry | GSAP via `useScrollReveal()` | Scroll `top 80%` | Section title + content block |
| Stat bar fills | GSAP | Scroll `top 80%` | `[data-stat-fill]` elements |
| Stub sections | none | none | Static — no animation applied |
| Nav interactions | Framer Motion | User interaction | Inherited from Phase 1 |
| CTA button hover | CSS transition | `:hover` pseudo | Not complex enough for library |
